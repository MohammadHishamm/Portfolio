## Overview

Hotdesk's backend runs on **AWS**. Beyond writing features, I worked on the infrastructure that runs them: background task queues, scheduled jobs, production data tasks, and investigating issues in running clusters.

## Key Features

- **Celery on SQS**: Created and configured Celery task queues on **AWS SQS**, including a dedicated queue for the access control feature.
- **Scheduled Jobs**: Scheduled recurring tasks with **AWS EventBridge**.
- **One-off Production Tasks**: Ran database migrations, data backfills, and rating recomputes on **ECS Fargate** from **AWS CloudShell**, on staging first and then production, following runbooks I wrote.
- **Investigations**: Investigated ECS cluster memory issues and a staging outage using **CloudWatch** logs and metrics, and verified providers' integration behaviour from production logs.
- **Docker**: Developed and tested inside Docker containers with Docker Compose (API, PostgreSQL/PostGIS, Redis, and Unleash), and upgraded our base image to Debian 12 with GitLab CI building and pushing it.

## Technologies Used

- **AWS** – ECS, Fargate, SQS, EventBridge, CloudWatch, CloudShell, RDS
- **Docker & Docker Compose** – development environment and images
- **GitLab CI** – building and pushing images
- **Celery & Redis** – background tasks

## Challenges and Learnings

Working on production taught me to make every rollout step verified and repeatable: write the runbook, try it on staging, check the numbers, then repeat on production.

## Outcome

Data rollouts for ratings, unified prices, and region search reached staging and production safely, and new background features run on their own queues and schedules.
